# 계획 2: DoorplateCore

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 포트 → 프로세스 → 프로젝트 판단과 종료를 맡는 Swift Package `DoorplateCore`, 그리고 진단 명령 `doorplate-scan`을 만든다.

**Architecture:** 시스템을 건드리는 것은 protocol 넷(`ProcessSource`, `FileProbe`, `DockerSource`, `ProcessSignaler`) 뒤에 둔다. 판단은 순수 함수(`ToolDetector`, `ProjectResolver`, `PortRoleDetector`, `HTTPGuess`, `Classifier`, `SnapshotBuilder`)로 한다. `Scanner` actor가 이 둘을 한 번의 조회로 묶는다. 테스트는 가짜 구현과 JSON 시나리오 fixture로 하고, 실제 시스템 테스트는 테스트가 직접 연 소켓과 직접 띄운 프로세스만 쓴다.

**Tech Stack:** Swift 6.4(tools-version 6.0, Swift 6 언어 모드), Swift Testing, Foundation, Darwin(libproc, POSIX 소켓), Dispatch, os(Logger).

**Spec:** `docs/specs/2026-11-04-doorplate-mvp-design.md`. 실험 결과 `docs/spikes/01-feasibility.md`를 먼저 읽는다(계획 1 완료가 전제).

## Global Constraints

- 브랜치는 `feat/core`이다. 계획 1이 `main`에 합쳐진 뒤 시작한다.
- 패키지 경로는 `Packages/DoorplateCore`, 플랫폼은 `.macOS(.v14)`, `swift-tools-version: 6.0`이다.
- `DoorplateCore`는 Foundation, Darwin, Dispatch, os만 import한다. AppKit, SwiftUI, Network, 외부 패키지는 쓰지 않는다. AppKit·SwiftUI 금지는 `scripts/check-core-imports.sh`가 CI에서 검사한다.
- 기록은 `Logger(subsystem: "io.github.junjuny0227.doorplate", category:)`로 남긴다. 카테고리는 `scan`(Scanner, libproc), `docker`(Docker 소켓), `terminate`(Terminator)이다.
- Core는 실행 중에 외부 명령(`lsof` 등)을 실행하지 않는다. 테스트가 띄울 수 있는 프로세스는 `/bin/sleep`, `/bin/sh`, `/usr/bin/true`뿐이다.
- 테스트는 자기가 띄운 프로세스에만 실제 시그널을 보낸다. 권한 오류(EPERM) 경로는 가짜 `ProcessSignaler`로만 시험한다.
- 네트워크는 Docker unix 소켓뿐이다.
- 경로는 Core 안에서 모두 `String`(절대 경로)으로 다룬다.
- 값(스펙에서 그대로 가져옴):
  - 종료 유예 10초, Docker 요청 시간 제한 1초, 오래 켜짐 기본값 `86_400`초
  - 보조 포트: jdwp 주소, Node `--inspect`(기본 9229), 35729(LiveReload)
  - HTTP가 아닌 포트: `5432, 3306, 6379, 27017, 9092, 11211`
  - Docker 소켓 후보: `~/.docker/run/docker.sock`, `/var/run/docker.sock`, `~/.orbstack/run/docker.sock`, `~/.colima/default/docker.sock`. 계획 1 결과가 다르면 결과를 따른다.
- 포맷은 `swift format`(저장소 루트 `.swift-format`)이다. 커밋 메시지는 영어 Conventional Commits, 문서는 한국어로 쓴다.
- 스펙과 다르게 정한 것은 같은 Task에서 스펙을 고친다(아래 "스펙 변경" 표).

## Review Focus

- **Docker를 끈 사용자**: 소켓 파일은 남아 있고 연결이 거부된다. 메뉴에 "응답 없음" 오류가 매번 뜨면 안 되고, Docker 구역이 그냥 사라져야 한다. → Task 9 `refusedSocketIsAbsent`
- **"다른 앱 표시"를 켠 사용자**: Docker Desktop, OrbStack, Colima(`limactl`)의 프로세스가 보여도 종료할 수 없어야 한다. 끄면 모든 컨테이너가 내려간다. → Task 2 런타임 규칙 테스트, Task 5 `runtimeAndOtherAppsAreNeverTerminable`
- **시스템 포트 표시**: 다른 앱 표시와 독립적으로 AirPlay·macOS 서비스를 숨기거나 표시한다. 5000·7000번을 쓰는 일반 서버는 그대로 보이고, 시스템 행은 서버 수·오래 켜짐·종료 대상에서 제외한다. → `systemVisibilityIsIndependentOfOtherApps`, `developmentServerOnAirPlayPortIsApp`
- **`~/Documents`에 프로젝트를 둔 사용자가 허락 창을 거부함**: 행이 사라지거나 실행 파일 이름(`node`)으로만 나오면 안 되고, 폴더 이름으로 나와야 한다. → Task 3 `deniedFallsBackToFolderName`
- **gunicorn, puma, `uvicorn --reload`처럼 소켓을 물려받는 서버**: 같은 포트가 worker 수만큼 나오면 안 되고, 종료 대상은 master여야 한다. → Task 5 `sharedSocketBelongsToTopmostAncestor`, Task 8 `inheritedSocketSharesID`
- **IntelliJ 내장 JBR로 실행한 Spring 앱**: 실행 파일이 `IntelliJ IDEA.app/Contents/jbr/...`에 있다. IDE로 오인해 숨기면 안 되고 `java` 앱으로 보여야 한다. → Task 2 `javaFromIDEBundledRuntimeIsApp`

**Interfaces:**

- Produces:
  ```swift
  public struct ToolMatch: Sendable, Equatable { public var tool: String?; public var section: Section; public var title: String? }
  public enum ToolDetector { public static func detect(_ process: ProcessRecord, parent: ProcessRecord?, ports: [UInt16]) -> ToolMatch }
  ```
  `title`은 프로젝트 이름 대신 쓸 제목이다(AirPlay, 숨긴 앱의 앱 이름). 나머지 경우는 `nil`이다.

규칙은 아래 순서로 처음 맞는 것을 쓴다. 규칙은 파일 안의 배열 하나로 둔다. "실행 파일 이름"은 `executablePath`의 마지막 마디이고, 경로가 없으면 `name`이다.
0. 컨테이너 런타임: 실행 파일 경로의 가장 바깥 `.app` 이름이 `Docker`, `OrbStack`, `Rancher Desktop`, `Podman Desktop` 중 하나이거나, 실행 파일 이름이 `limactl`, `vfkit`, `gvproxy`, `krunkit`이거나 `qemu-system-`으로 시작하면 → `("container runtime", .hidden(.otherApp), title: 앱 이름 또는 실행 파일 이름)`. `.app` 이름이 `Docker`이면 title은 `Docker`다.
1. node(실행 파일 이름이 `node`이거나, 프로세스 이름·argv[0]이 `next-server`로 시작): argv 원소가 `/node_modules/<F>/`를 포함하거나, `/node_modules/.bin/<F>`로 끝나거나, `<F>`와 같으면 → `(F, .app)`. F는 `vite, next, nuxt, astro, remix, webpack` 순서로 찾는다. 이름이나 argv[0]이 `next-server`로 시작하면 → `("next", .app)`. 그 밖의 node → `("node", .app)`.
2. java(이름 `java`):
   - argv에 `org.gradle.launcher.daemon.bootstrap.GradleDaemon`이 있으면 → `("gradle daemon", .hidden(.devTool))`
   - argv에 `org.jetbrains.kotlin.daemon.KotlinCompileDaemon`이 있으면 → `("kotlin daemon", .hidden(.devTool))`
   - 부모 argv에 `GradleDaemon`이 있으면 → `("gradle", .app)`
   - 부모 argv에 `org.codehaus.plexus.classworlds.launcher.Launcher`가 있으면 → `("maven", .app)`
   - 그 밖 → `("java", .app)`
