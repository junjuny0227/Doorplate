# 계획 5: 제품 소개 페이지

## 목표

Repot 소개 페이지의 네이티브 macOS 문법을 이어받아 Doorplate의 기능, 실제 화면, 설치와 첫 실행을 설명한다. `site/`에 영어·한국어·일본어·중국어(간체) 정적 페이지를 만들고 GitHub Pages에 배포한다.

## Global Constraints

- 브랜치는 `feat/site`, 제품 문구는 네 README가 기준이다. 앱 코드는 바꾸지 않는다.
- 앱 외부 의존성은 여전히 Sparkle 하나다. React 19, Vite, TypeScript, Vitest, Biome과 타입 패키지는 사이트 전용 npm 개발·빌드 의존성으로만 허용한다. pnpm 버전과 lockfile을 고정한다.
- GitHub Pages는 기존 LEGACY 방식과 `gh-pages` 소스를 유지한다. 사이트 산출물은 기존 `appcast.xml` 옆에 커밋하고 Pages build API를 호출한다. `actions/deploy-pages`와 Pages 설정 변경은 금지한다.
- 배포는 appcast 워크플로와 같은 `appcast-gh-pages` 동시성 그룹을 쓴다. `appcast.xml`을 삭제·수정하지 않고 배포 전후 바이트 해시를 비교한다. 배포 전에 원격 피드를 보관한다.
- 다운로드는 `project.yml`의 `MARKETING_VERSION`으로 만든 버전별 zip 주소다. 배포 전에 공개 릴리스와 자산 존재를 확인하고 실패하면 이전 배포를 유지한다.
- 추적·분석·쿠키·외부 폰트·CDN은 없다. 시스템 폰트, 밝은/어두운 모드, 모바일, 키보드 접근성을 지원한다.
- 아이콘과 화면은 기존 원본에서 빌드 때 복사한다. 바이너리를 git에 중복 저장하지 않는다.
- 보호된 `AGENTS.md`는 수정하지 않고 필요한 명령 표와 경계 문구를 인계 문서에 남긴다.

## 작업

1. 계획과 스펙을 먼저 커밋한다.
2. Repot의 1080px 컨테이너, 64/36/17/14px 타입 스케일, 12px 카드와 버튼 문법을 추출한다. Doorplate 아이콘의 남색·오렌지·황동색으로 조정한다.
3. 네 언어의 Header, Hero, Screenshot, 기능, 스택 표, 원칙, 설치·첫 실행, Footer를 구현한다. 언어 링크와 title/description/canonical/hreflang을 정적으로 만든다.
4. 로케일 키 일치, 다운로드 버전, head, 섹션·접근성 마크업, 배포의 appcast 보존을 테스트한다.
5. CI 사이트 job과 LEGACY Pages 배포를 추가한다. 기존 Swift job은 그대로 둔다.
6. 로컬 검사와 빌드 미리 보기의 밝은/어두운 1280px 영어·한국어 및 390px 화면을 확인한다.
7. PR의 모든 검사를 기다린 뒤 병합하고 실제 Pages 워크플로와 사이트·피드 해시를 확인한다.

## 확인

- `pnpm install`
- `pnpm exec biome ci .`
- `pnpm --filter @doorplate/site test`
- `pnpm --filter @doorplate/site build`
- `actionlint .github/workflows/*.yml`
- `swift format lint --strict --recursive Packages App`
- 빌드 화면 캡처를 직접 보고 모바일 넘침·누락 이미지·CJK 줄바꿈을 확인한다.
- PR 검사 전체 통과, main Pages 배포 성공, 공개 페이지 200 및 배포 전후 appcast SHA-1 동일.

## Review Focus

- appcast 삭제 또는 변경, Pages 소스 전환, 동시 배포 경쟁은 배포를 막는다.
- 공개하지 않은 버전의 다운로드를 배포하지 않는다.
- README와 다르게 과장하거나 첫 실행의 미공증 경고를 숨기지 않는다.
- 사이트 의존성을 Swift 앱에 넣지 않는다.
