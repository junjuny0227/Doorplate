# 계획 3: 메뉴바 앱

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `DoorplateCore`의 Snapshot을 macOS 메뉴바의 네이티브 메뉴로 보여 주고, 열기·복사·종료·설정·업데이트를 동작하게 한다.

**Architecture:** 메뉴 모양과 동작 흐름은 AppKit을 쓰는 별도 패키지 `DoorplateMenu`에 둔다. 이렇게 하면 `swift test`로 검증할 수 있다. 대상은 `MenuBuilder`, `StatusBadge`, `StopCoordinator`, `SettingsStore`, 문구다. XcodeGen 앱 타깃 `Doorplate`는 상태 항목, 타이머, `NSWorkspace` 동작, 확인 창, 설정 창, 로그인 항목, 업데이트를 연결만 하고, 빌드와 수동 점검으로 확인한다.

**Tech Stack:** Swift 6.4, AppKit(`NSStatusItem`, `NSMenu`), SwiftUI(설정 창), ServiceManagement(`SMAppService`), Sparkle 2, XcodeGen.

**Spec:** `docs/specs/2026-11-04-doorplate-mvp-design.md` (4, 6.2, 7.7, 8, 9, 10, 11, 12.3절). `docs/spikes/01-feasibility.md`와 계획 2의 `DoorplateCore` 공개 타입을 먼저 읽는다.

## Global Constraints

- 브랜치는 `feat/app`이다. 계획 2가 `main`에 합쳐진 뒤 시작한다.
- 번들 ID `io.github.junjuny0227.doorplate`, 로그 subsystem도 같은 값이다. 배포 대상 macOS 14.0, `LSUIElement = true`(Dock 아이콘 없음).
- ad-hoc 서명(`CODE_SIGN_IDENTITY=-`), App Sandbox 끔, Hardened Runtime 끔.
- 외부 패키지는 Sparkle 하나다. 버전은 계획 1에서 확인한 `2.10.1`을 `exactVersion: 2.10.1`로 고정한다.
- 사용자에게 보이는 문구는 모두 `DoorplateMenu`의 `L10n`을 거친다. 영어 원본(`en.lproj/Localizable.strings`)과 한국어(`ko.lproj/Localizable.strings`)에 같은 키를 둔다. 복수형이 필요한 문구는 없다.
- 값:
  - 조회 주기 5초
  - 메뉴 머리글 실패 표시는 `ScanOutcome.failedAt`이 있을 때
  - 종료 유예 10초(계획 2 `Terminator` 기본값)
  - 오래 켜짐 설정 범위 1–168시간, 기본 24시간
  - 터미널 기본값 `com.apple.Terminal`
- 메뉴 행 문구 형식: 행 `"<포트>  <제목>[ · <오래 켜짐>]\t<도구>"`. ` · <오래 켜짐>`은 `isLongRunning`일 때만 붙이고, 값은 `L10n.format(.rowLongRunning, DurationText.short(now - startedAt))`이다(en `· 3d`, ko `· 3일째`). 이 꼬리표(` · ` 포함)는 `attributedTitle`에서 `.foregroundColor: NSColor.systemOrange`로 쓴다. 오른쪽 탭 정지에 도구 이름을 맞추고, `attributedTitle`에는 `.font: NSFont.menuFont(ofSize: 0)`를 넣는다. 컨테이너 행의 도구 자리는 계획 2가 채운 `tool`(Compose면 컨테이너 이름, 아니면 이미지 짧은 이름)이다. ⌥ 대체 항목은 `L10n.format(.rowStop, port, title)`.
- 기록은 `Logger(subsystem: "io.github.junjuny0227.doorplate", category:)`로 남긴다. 카테고리는 `menu`(메뉴, 동작), `update`(업데이트)이다.
- 메뉴 명령은 `ActionPerformer` 하나가 받는다(Task 3에서 만들고 Task 4에서 채움). 설정 창, 업데이트, 종료는 `AppDelegate`가 넘긴 클로저로 처리한다.
- 브라우저 주소는 `http://localhost:<포트>`, 복사 주소는 `localhost:<포트>`이다.
- 실험 결과에 따라 갈리는 곳은 Task 안에 "실험 결과가 A면 / B면"으로 둘 다 적는다. 결과 문서에 적힌 쪽만 구현한다.

## Review Focus

- **메뉴가 열린 채로 서버가 사라지거나 생김**: 열린 메뉴가 닫히거나 엉뚱한 항목을 가리키면 안 된다. 행은 pid가 아니라 `ServerEntry.id`와 그 시점의 `Target`(시작 시각 포함)을 들고 있다. 종료는 계획 2의 pid 재확인을 거친다. → Task 2 `commandCarriesTargetSnapshot`, Task 3 수동 점검 3번
- **같은 서버를 두 번 종료**: ⌥ 클릭을 연달아 하거나, 종료 중에 하위 메뉴의 Stop을 누르는 경우다. 두 번째 요청은 무시되어야 한다. → Task 4 `secondStopWhileStoppingIsIgnored`
- **선택한 터미널 앱이 지워짐**: 설정에 남은 번들 ID의 앱이 없으면 Terminal로 열어야 한다. → Task 5 `missingTerminalFallsBackToTerminal`
- **한국어로 쓰는 사용자**: 영어에만 있고 한국어에 빠진 키가 있으면 그 문구만 영어로 섞여 나온다. → Task 1 `everyKeyHasKorean`
- **AirPlay만 켜져 있는 기기**: 메뉴바에 숫자 없이 아이콘만 보이고, 메뉴에는 "No servers running"과 시스템 행이 함께 보여야 한다. → Task 1 `badgeHiddenWhenZero`, Task 2 `emptyStateKeepsSystemSection`

### Task 2: MenuBuilder

**Files:**
- Create: `Packages/DoorplateMenu/Sources/DoorplateMenu/MenuCommand.swift`

- Create: `Packages/DoorplateMenu/Sources/DoorplateMenu/StatusDot.swift`
- Test: `Packages/DoorplateMenu/Tests/DoorplateMenuTests/MenuBuilderTests.swift`, `Support/Entries.swift`
- Modify: 스펙 8절, 8.2 (사용자 시안)

**Interfaces:**
- Consumes: Task 1의 `L10n`, `DurationText`, `PathText`. `DoorplateCore`의 `ScanOutcome`, `ServerEntry`, `Target`, `PortRole`
- Produces:
  ```swift
  public struct EntryRef: Equatable, Sendable { public var id: String; public var target: Target; public var title: String; public var port: UInt16 }
  public enum MenuCommand: Equatable, Sendable {
    case openInBrowser(URL), revealInFinder(String), openInTerminal(String), copy(String)
    case stop(EntryRef), openSettings, checkForUpdates, openUpdatePage(URL), quit
  }
  public enum UpdateMenuItem: Equatable, Sendable { case checkForUpdates, available(version: String, page: URL), pending(version: String), none }
  // pending: Sparkle이 찾았지만 창을 띄우지 않은 예약 업데이트(Task 6 A). 제목 menu.updateAvailable, 명령 .checkForUpdates
  public struct MenuState: Equatable, Sendable {
    public var stopping: Set<String> = []                       // ServerEntry.id
    public var update: UpdateMenuItem = .checkForUpdates
    public init()
  }
  @MainActor public protocol MenuCommandHandler: AnyObject { func perform(_ command: MenuCommand) }
  @MainActor public final class MenuBuilder: NSObject {
    public init(handler: MenuCommandHandler, home: String, now: @escaping () -> Date)
    public func populate(_ menu: NSMenu, outcome: ScanOutcome?, state: MenuState)   // menu의 항목을 모두 바꾼다
    public func refresh(_ menu: NSMenu, outcome: ScanOutcome?, state: MenuState)    // 열린 메뉴용. 아래 규칙
  }
  public enum StatusDot { case running, longRunning, docker, system
                          @MainActor public func image() -> NSImage }   // 8pt 원, system은 테두리만
  ```
  항목의 동작은 `representedObject`에 `MenuCommand`를 담은 상자로 두고, target은 `MenuBuilder`, action은 `itemChosen(_:)`이다. `itemChosen`이 `handler.perform`을 부른다. 행 항목의 `identifier`는 `ServerEntry.id`이다.
- `refresh`: 새 결과의 행 id 목록(순서 포함)과 구역 구성이 메뉴에 있는 것과 같으면, 항목을 새로 만들지 않고 기존 `NSMenuItem`의 제목, 이미지, 활성 여부, 대체 항목, 하위 메뉴 항목의 활성 여부만 바꾼다. 열려 있는 하위 메뉴가 닫히지 않게 하려는 것이다. 다르면 `populate`와 같다.
- 메뉴 구성 순서(스펙 8절):
  1. 머리글(비활성): `failedAt`이 있으면 `header.failed`(기간은 `DurationText`), 없으면 `header.running`(`badgeCount`)
  2. 앱 행들. `apps`와 `docker`가 모두 비면 `menu.empty`
  3. 구분선 + 시스템 행들(있을 때)
  4. 구분선 + `menu.docker` 머리글 + 컨테이너 행들. `dockerStatus == .notResponding`이면 머리글 아래에 `menu.dockerNotResponding`(비활성). `.notResponding`이 아니고 컨테이너 행이 없으면 구역 전체를 생략한다
  5. 구분선 + `menu.hidden`(하위 메뉴: 숨긴 항목마다 `"<포트>  <제목>"` 비활성 행). 숨김 0개면 생략
  6. 구분선 + 업데이트 항목(`state.update`가 `.none`이 아니면) + `menu.settings`(⌘,) + `menu.quit`(⌘Q)
- 행:
  - 제목은 Global Constraints의 형식이고, 이미지는 `StatusDot`이다. 오래 켜짐이면 `longRunning`, 컨테이너는 `docker`, 시스템은 `system`.
