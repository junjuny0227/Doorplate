# 계획 6: git 브랜치 표시

## 목표

앱 서버 행의 프로젝트 이름 뒤에 그 프로젝트의 현재 git 브랜치를 회색 글자로 붙인다. 같은 프로젝트를 워크트리로 여러 개 띄웠을 때 어느 행이 어느 브랜치인지 구분하고, 띄운 서버가 예상한 브랜치인지 메뉴에서 확인할 수 있게 한다.

```
● 5173  @acme/web · feat/login               vite ▸
● 5174  @acme/web · main                     vite ▸
● 8080  shop-api · main · 3일째            gradle ▸
```

## Global Constraints

- 브랜치는 `feat/git-branch`, 버전은 0.4.0이다(새 기능).
- `git` 명령을 실행하지 않는다. 이미 찾은 저장소 루트에서 HEAD 파일 하나만 `FileProbe.read`로 읽는다(5절 원칙, Core 외부 명령 금지).
- 브랜치 읽기는 프로젝트 이름과 같은 조회 작업에서 한다. 보호 폴더별 작업 줄과 30초 캐시(7.5절)를 그대로 쓰고, 새 큐나 타이머를 만들지 않는다.
- 외부 의존성을 추가하지 않는다.
- 새 문구는 `L10n`을 거치고 `en`, `ko`, `ja`, `zh-Hans`에 같은 키를 둔다.

## 결정과 이유

| 결정 | 이유 |
|---|---|
| 항상 표시(기본 브랜치 포함) | 사용자 결정(2026-11-27). 예상한 브랜치에서 서버를 띄웠는지도 확인할 수 있다 |
| 설정 토글, 기본 켜짐 | 사용자 결정(2026-11-27). 행이 길어지는 게 거슬리면 끈다 |
| HEAD 파일만 읽는다 | `git` 실행은 Core 경계 위반이고, `refs/heads/<이름>`은 HEAD 한 줄에 그대로 있어 packed-refs를 읽을 필요가 없다 |

| 24자에서 자르고 `…` | 메뉴 폭이 긴 브랜치 이름에 끌려 넓어지지 않게 한다. 전체 이름은 Core가 가지고 있고 자르기는 메뉴가 한다 |
| 캐시를 공유해 최대 30초 늦게 반영 | 브랜치만 따로 매번 읽으면 보호 폴더에서 권한 대기 중인 조회가 다른 행을 막는 문제(7.5절, PR #70)를 다시 만든다. 서버를 다시 띄우면 즉시 반영된다 |
| 설정은 `SnapshotSettings`로 | 다른 표시 설정과 같은 경로(설정 → 재조회 → Snapshot)다. 메뉴에 새 상태를 늘리지 않는다 |
| Docker 행에는 없음 | 컨테이너의 작업 폴더는 이 Mac의 경로가 아니다 |

## 브랜치 읽기 규칙

저장소 루트 `R`(이미 `repositoryRoot`로 찾음)에서:

1. `R/.git`을 파일로 읽어 `gitdir: <경로>`로 시작하면(워크트리, 서브모듈) 그 경로의 `HEAD`를 읽는다. 상대 경로는 `R` 기준이다.
2. 아니면 `R/.git/HEAD`를 읽는다.
3. HEAD가 `ref: refs/heads/<이름>`이면 `<이름>`(슬래시 포함 그대로). `ref: <다른 ref>`면 `refs/`를 뗀 나머지. 40자 또는 64자 16진수면 앞 7자리. 그 밖이거나 읽지 못하면 브랜치 없음.
4. 권한 거부·읽기 실패는 브랜치만 비우고 프로젝트 이름은 지금처럼 정한다.

## 작업

1. 이 계획과 스펙을 먼저 커밋한다(문서 PR).
2. `GitHead`와 테스트: 브랜치, 슬래시 브랜치, detached(SHA-1, SHA-256), 기타 ref, 빈 값·쓰레기, `gitdir:` 절대·상대 경로.
3. `ProjectResolver`가 브랜치를 채운다. 테스트: 일반 저장소, 워크트리, 모노레포 하위 패키지(루트의 HEAD), `.git` 없음, 권한 거부, `inaccessibleProject`는 브랜치 없음.
4. `ServerEntry.branch`, `SnapshotSettings.showGitBranch`(기본 참, 키 없으면 참으로 읽음), `SnapshotBuilder`가 꺼짐일 때 비움. 시나리오 `git-worktree`를 추가하고 golden을 재생성해 diff를 읽는다. 기존 golden은 브랜치가 없으면 바뀌지 않아야 한다.
5. 메뉴: 제목 뒤 ` · <브랜치>`를 `secondaryLabelColor`로, 24자 넘으면 23자 + `…`, 오래 켜짐 꼬리표는 그 뒤. 설정 토글과 네 언어 문구.
6. README·사이트 기능 문구, 수동 점검표.
7. 로컬 검사, Debug 빌드로 실제 메뉴 확인(워크트리 두 개에 서버 하나씩), PR 검사 통과 후 병합, 0.4.0 릴리스.

## Review Focus

- Core에서 `git`이나 다른 외부 명령을 실행하면 막는다.
- 브랜치 읽기 때문에 보호 폴더 조회가 늘거나 새 대기 경로가 생기면 막는다.
- 브랜치가 없는 저장소·Docker 행·숨김 목록의 모양이 바뀌면 안 된다.
- 기존 golden이 브랜치 외의 이유로 바뀌면 안 된다.
