# 계획 4: 배포

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 태그 하나로 Universal 앱 zip을 담은 draft 릴리스를 만든다. 공개하면 업데이트 피드와 Homebrew tap을 갱신해 첫 릴리스 0.1.0(beta)을 낸다.

**Architecture:** 빌드는 저장소의 스크립트 하나(`scripts/build-release.sh`)가 맡아 로컬과 CI에서 똑같이 돈다. 태그 push가 draft 릴리스를 만들고, 사용자가 공개하면 두 번째 워크플로가 Sparkle appcast를 갱신한다. appcast 항목은 작은 Swift 도구(`Packages/ReleaseTools`)가 쓰고, `swift test`로 검증한다. Homebrew cask는 템플릿과 스크립트로 만들어 별도 tap 저장소에 반영한다.

**Tech Stack:** bash, GitHub Actions(macOS 러너), `gh`, XcodeGen, Sparkle 도구(`sign_update`), Swift(`XMLDocument`), Homebrew.

**Spec:** `docs/specs/2026-11-04-doorplate-mvp-design.md` 13절. 계획 1 결과 문서의 13.3절 결정(Sparkle을 쓰는지)을 먼저 확인한다.

## Global Constraints

- 브랜치는 `ci/release`이다. 계획 3이 `main`에 합쳐진 뒤 시작한다.
- 원격 push, 태그 생성, 릴리스 공개, tap 저장소 생성, GitHub Pages 설정, Secrets 등록은 실행 전에 사용자 확인을 받는다.
- 릴리스는 워크플로가 draft로 만들고, 사용자가 확인한 뒤 공개한다. 0.x는 prerelease가 아닌 정식 릴리스이고, 이름은 `Doorplate <버전> (beta)`이다.
- 태그는 `v<MARKETING_VERSION>`이다(예: `v0.1.0`). 다르면 빌드가 실패한다.
- 산출물은 `dist/Doorplate-<버전>.zip`(`ditto -c -k --keepParent`)과 `dist/Doorplate-<버전>.zip.sha256`이다. Universal(`arm64 x86_64`), ad-hoc 서명, 공증 없음.
- Sparkle EdDSA 비밀 키는 로컬 키체인(계정 `doorplate`)과 GitHub Secret `SPARKLE_ED_PRIVATE_KEY`에만 둔다. 로그나 파일에 남기지 않는다. CI에서는 `umask 077` 임시 파일에 쓰고, 단계가 끝나면 지운다.
- appcast URL은 `https://junjuny0227.github.io/Doorplate/appcast.xml`(`gh-pages` 브랜치)이다.
- Homebrew tap은 `junjuny0227/homebrew-tap`, cask 이름은 `doorplate`이다.
- 실험 결과가 "Sparkle 실패"(계획 3 Task 6 B)면 Task 3과 Task 4의 appcast 부분을 하지 않는다. cask에서는 `auto_updates true`를 뺀다.

## Review Focus

- **태그와 앱 버전이 다름**: `v0.1.1`을 달았는데 앱이 `0.1.0`이면 업데이트가 영원히 반복된다. → Task 1 `check-version` 실패 확인
- **Intel Mac 사용자**: arm64만 빌드되면 실행이 안 된다. → Task 1 `lipo -archs` 확인
- **Sparkle 내부 도우미의 서명**: Sparkle 안쪽 XPC·Autoupdate 서명이 깨지면 업데이트 뒤 앱이 열리지 않는다. → Task 1 `codesign --verify --deep --strict`
- **appcast 갱신이 이전 항목을 지우거나 길이·서명을 틀리게 씀**: 기존 사용자가 업데이트를 못 받는다. → Task 3 `keepsExistingItems`, `writesEnclosureAttributes`
- **cask sha256이 릴리스 파일과 다름**: `brew install`이 실패한다. → Task 5에서 릴리스의 `.sha256` 파일 값으로 cask를 만들고, 설치로 확인

### Task 3: appcast 도구 (Sparkle을 쓸 때만)

**Files:**
- Create: `Packages/ReleaseTools/Package.swift` (library `AppcastKit`, executable `appcast`, 플랫폼 `.macOS(.v14)`)
- Create: `Packages/ReleaseTools/Sources/AppcastKit/Appcast.swift`
- Create: `Packages/ReleaseTools/Sources/appcast/main.swift`
- Test: `Packages/ReleaseTools/Tests/AppcastKitTests/AppcastTests.swift`
- Modify: `.github/workflows/ci.yml` (`swift test --package-path Packages/ReleaseTools`)
- Modify: 스펙 6.3 (저장소 모양에 `Packages/ReleaseTools`, `scripts/`, `packaging/homebrew/` 추가)

**Interfaces:**
- Produces:
  ```swift
  public struct AppcastItem: Equatable {
    public var version: String          // sparkle:shortVersionString, 예 "0.1.0"
    public var build: String            // sparkle:version, 예 "1"
    public var url: URL                 // enclosure url
    public var length: Int              // enclosure length
    public var edSignature: String      // sparkle:edSignature
    public var minimumSystemVersion: String = "14.0"
    public var publishedAt: Date
  }
  public enum Appcast {
    public static func empty(title: String, link: URL) -> String
    public static func adding(_ item: AppcastItem, to xml: String) throws -> String    // 새 항목을 맨 앞에 넣는다. 같은 build가 있으면 바꾼다
    public static func parseSignOutput(_ output: String) throws -> (edSignature: String, length: Int)  // sign_update 출력: sparkle:edSignature="…" length="…"
  }
  ```
- 명령: `swift run --package-path Packages/ReleaseTools appcast add --file <appcast.xml> --version <v> --build <b> --url <url> --sign-output "<sign_update 출력>"`. 파일이 없으면 `empty(title: "Doorplate", link: https://github.com/junjuny0227/Doorplate)`로 시작한다.

- [ ] **Step 1: 실패하는 테스트 작성**

- `emptyHasSparkleNamespace`: `empty`의 루트 `rss`에 `xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle"`가 있고 `channel/item`이 0개
- `writesEnclosureAttributes`: 항목 하나를 더하면 `enclosure`의 `url`, `length="1234"`, `type="application/octet-stream"`, `sparkle:edSignature`가 있고, `sparkle:version`, `sparkle:shortVersionString`, `sparkle:minimumSystemVersion` 요소가 있다
- `keepsExistingItems`: 0.1.0 다음에 0.1.1을 더하면 항목 2개, 첫 번째가 0.1.1
- `replacesSameBuild`: 같은 build를 다시 더하면 항목 수가 그대로이고 서명이 새 값이다
- `parsesSignUpdateOutput`: `sparkle:edSignature="abc+/=" length="1234"` → `("abc+/=", 1234)`. 형식이 다르면 throw

- [ ] **Step 2: 실패 확인 → 구현 → 통과 확인**

Run: `swift test --package-path Packages/ReleaseTools`
Expected: 처음에는 FAIL, 구현 후 PASS

- `appcast.yml`:
  - `on: release: types: [published]`, `permissions: contents: write`.
  - zip 자산을 받는다. 계획 3에서 고정한 버전의 Sparkle 배포판(`https://github.com/sparkle-project/Sparkle/releases/download/<버전>/Sparkle-<버전>.tar.xz`)에서 `bin/sign_update`를 꺼낸다.
  - `SPARKLE_ED_PRIVATE_KEY`를 `umask 077` 임시 파일에 쓰고 `sign_update --ed-key-file <파일> <zip>`을 실행한 뒤 바로 파일을 지운다.
  - `gh-pages` 브랜치를 checkout한다. 브랜치가 없으면 orphan으로 만든다.
  - `appcast add`로 `appcast.xml`을 갱신한다. build는 앱의 `CFBundleVersion`이다(`/usr/libexec/PlistBuddy`로 읽음).
  - `github-actions[bot]`으로 커밋하고 push한다.
- `docs/checklists/release.md` 순서:
  1. `project.yml`의 `MARKETING_VERSION`과 `CURRENT_PROJECT_VERSION`(이전보다 1 큼)을 올리는 PR
  2. 합친 뒤 태그(사용자 확인)
  3. draft 확인
  4. 공개(사용자)
  5. appcast 반영 확인(`curl -s <appcast URL> | grep shortVersionString`)
  6. cask 갱신(Task 5)

**Interfaces:**
- 템플릿:
  ```ruby

    version "{{VERSION}}"
    sha256 "{{SHA256}}"
    url "https://github.com/junjuny0227/Doorplate/releases/download/v#{version}/Doorplate-#{version}.zip"
    name "Doorplate"
    desc "Menu bar app that shows which project owns each local port"
    homepage "https://github.com/junjuny0227/Doorplate"
    auto_updates true                       # Sparkle을 쓸 때만
    depends_on macos: ">= :sonoma"
    app "Doorplate.app"
    zap trash: "~/Library/Preferences/io.github.junjuny0227.doorplate.plist"
    caveats <<~EOS
      Doorplate is not notarized. The first time you open it, macOS blocks it.
      Open System Settings > Privacy & Security and click "Open Anyway".
    EOS
  end
  ```
